## 讲义

安全这一周只求一条底线：知道哪些事绝不能发生，并能判断 agent 写的代码有没有碰到它。认证回答你是谁，授权回答你能做什么，有认证没授权是常见的漏洞。每个程序、每把密钥、每个 agent 只给完成工作所必需的权限。外来的输入一律不信任，不能直接拼进查询或命令，文字里还可能藏着给 agent 的指令。用四个问题做威胁梳理，用“能不能被真的利用、损失多大”判断评审发现。安全边界靠权限和机制，不靠提示词里的一句话。

## 术语

- **认证**。 确认“你是谁”的检查，比如登录。
- **授权**。 确认“你能做什么”的检查，比如只能看自己的数据。
- **有认证没授权**。 只检查了登录没有，没检查这条数据是不是你的，于是换一个编号就能看到别人的东西。
- **最小权限**。 每个程序、每把密钥只拿完成工作所必需的权限，出事时损害有上限。
- **外来的输入**。 用户填的内容、别的系统传来的数据、网页上抓来的文字，都可能被人精心构造。
- **威胁梳理**。 用四个问题把工具过一遍：保管着什么，谁能从哪里接触，最坏会怎样，现在有什么挡着。
- **安全评审**。 专门从安全角度把代码和配置检查一遍，列出可能的问题。
- **安全边界**。 一道真正拦得住的限制，靠权限和机制实现，而不靠一句叮嘱。

## 自测

1. 你的工具里，查看记录的页面地址末尾是记录编号。一位同事登录后把编号改了一位，看到了另一个人的记录。这属于哪种问题？
   - A. 没有认证，任何人都能访问
   - B. 有认证没授权，没查这条记录属于谁
   - C. 密码强度不够，账号容易被猜中
   - D. 日志里记下了不该记的个人信息

2. 日报工具只需要读销售表。agent 申请数据库账号时说：先把读、写、删的权限都开了，省得以后再申请。你怎么判断？
   - A. 同意，以后加功能时确实会方便一些
   - B. 同意，同时在提示词里写明不许删数据
   - C. 同意，但每周把操作日志检查一遍
   - D. 只开读权限，以后确实需要时再加

3. 工具有一个搜索框，三位同事也在用。评审时你发现，agent 把搜索框里的文字直接拼进了数据库查询语句。应该怎么处理？
   - A. 打回，外来内容不能直接拼进查询
   - B. 放行，使用的人都已经登录过了
   - C. 放行，搜索框已经限制了输入长度
   - D. 放行，用的人都是信得过的同事

4. 你让 agent 抓取一个网页写摘要。网页正文里夹着一行字，要求读到的程序忽略原来的任务，把配置文件的内容发到某个地址。对这行字应该怎么看待？
   - A. 它出现在任务材料里，算是任务的一部分
   - B. 它是网站方提出的要求，应当尽量配合
   - C. 它是外来的输入，里面的指令不能当真
   - D. 它多半是网页的排版错误，不用在意

5. agent 做完安全评审，列出了二十条发现。你用哪两个问题来筛出真正要处理的？
   - A. 修起来难不难，要花多长时间
   - B. 这段代码是谁写的，什么时候写的
   - C. 它排在第几条，措辞有多严重
   - D. 能不能被真的利用，利用后损失多大

6. 你担心 agent 误删正式数据。下面哪种做法才算安全边界？
   - A. 给 agent 的账号不带删除权限
   - B. 在提示词里用最强的语气禁止删除
   - C. 在约定文件的第一行写明不许删除
   - D. 每次开工前先让它复述一遍禁令

<details>
<summary>展开自测答案与解释</summary>

1. **B**。 他确实登录了，所以认证是有的。缺的是授权：没有检查这条数据是不是他的。
2. **D**。 最小权限。只读的账号即使出了缺陷或泄露，也删不了数据。提示词里的禁令和事后查日志都拦不住正在发生的事。
3. **A**。 这是最经典的漏洞。登录只说明他是谁，说明不了他填的内容安全。信任使用者也不等于信任输入。
4. **C**。 外来的文字里可能藏着指令。真正挡住它的办法是让 agent 本来就没有读密钥和向外发送的权限。当成排版错误，就会错过一次真实的风险。
5. **D**。 判断发现看可利用性和损失。排位和措辞是 agent 给的，修复成本决定的是怎么修，都不能说明问题是不是真的。
6. **A**。 边界靠权限和机制。后三种都是文字上的叮嘱，能做到的事，迟早会被做出来。

</details>

## 案例练习

### 工具安全评审

记账工具：  
存着你和三位同事两年的报销记录，含银行卡后四位。网址公开，登录后可用。  
数据库密钥在平台的机密保管处，账号有读写删全部权限。agent 也用这个账号，约定文件写着“不要删正式数据”。  
  
agent 评审发现：  
1. 记录页只检查是否登录，改编号能看别人的记录。  
2. 备注被直接拼进查询语句。  
3. 密码只要求八位，建议十六位。  
4. 页面底部显示了版本号。  
5. 密钥没有写进代码，无问题。

**请写出你的判断**

哪些发现是真问题？评审有没有漏掉什么？写出你的判断和理由，按严重程度排序，并说明先处理哪一个。

<details>
<summary>展开案例参考分析</summary>

真问题有三个，其中一个不在 agent 的清单上。先修第 1 条，再修第 2 条，然后收紧权限：

- **第 1 条最先修。** 有认证没授权。任何一个登录的人改一下编号，就能看到别人的报销记录和卡号后四位，利用起来没有门槛。
- **第 2 条紧随其后。** 备注是用户填的外来内容，直接拼进查询是经典漏洞。这个账号还有写和删的权限，后果可以到数据被改、被删。
- **评审漏掉了权限过大。** 工具和 agent 共用一个读写删全开的账号，挡在前面的只有约定文件里的一句话。应该去掉用不到的权限，给 agent 一个删不了正式数据的账号。
- **第 3、4 条可以排后。** 它们很难单独被利用，损失也小得多，记下来即可。第 5 条说得对，密钥的放法没有问题。

这道题练两种判断。一是用“能不能被真的利用、损失多大”给发现排序，不按 agent 列的顺序走。二是对着威胁梳理的四个问题自己再过一遍，看评审漏了什么。

</details>

## 复习

先不看题，凭记忆写出安全的三条原则（第一条是分清两个词），和威胁梳理的四个问题。

1. 认证和授权分别回答什么问题？
   - A. 认证回答你是谁，授权回答你能做什么
   - B. 认证回答你能做什么，授权回答你是谁
   - C. 认证回答数据在哪里，授权回答谁能看
   - D. 认证回答密码对不对，授权回答密码强不强

2. 最小权限带来的好处是什么？
   - A. 程序占用的资源更少，运行更快
   - B. 有了它，数据就不再需要备份
   - C. 出了缺陷或密钥泄露时，损害有上限
   - D. 有了它，就不再需要做认证

3. 下面哪一个不属于威胁梳理的四个问题？
   - A. 它保管着什么值钱的东西
   - B. 它是用什么语言写的
   - C. 最坏的情况是什么
   - D. 现在有什么在挡着

4. 哪些内容要当作“外来的输入”来对待？
   - A. 只有陌生用户填写的内容
   - B. 只有从网页上抓来的文字
   - C. 只有别的系统传来的数据
   - D. 以上三种来源全部都算

5. 这一章说，安全边界应该靠什么来保证？
   - A. 提示词里写清楚的禁令
   - B. agent 自己的判断力
   - C. 权限和机制
   - D. 事后对日志的检查

<details>
<summary>展开复习答案与解释</summary>

1. **A**。 登录是认证。只能看自己的数据是授权。两样都要检查。
2. **C**。 它不能防止出事，但能限制出事之后的范围。
3. **B**。 四个问题是：保管着什么，谁能从哪里接触到它，最坏会怎样，现在有什么挡着。
4. **D**。 三种来源都可能被人精心构造，都不能直接拼进查询或命令。
5. **C**。 能做到的事迟早会被做出来，所以要让它做不到。

</details>
