用于入门第一课。重点看规则、反例和验收条件怎样进入规格。

## 讲义

意图是一句话，说清谁、在什么情况下、遇到什么麻烦，里面不写解决方案。规格把“做成什么样算完成”写到可以检查的程度，要写四样：范围、非目标、验收条件、边界情况。判断一条验收条件合不合格，就问能不能设计一个检查，让它明确地通过或者不通过。agent 起草的规格由你来审，看五点：有没有扩大范围，非目标写了没有，验收条件能不能检查，有没有没说出来的假设，出错时怎样。最后让 agent 照规格做一个粗糙的原型，卡住的地方回去改规格。

## 术语

- **意图**。 一句话，说清要解决谁的什么问题，里面不写解决方案。
- **规格**。 把“做成什么样算完成”写到可以检查的程度的一份文档。
- **范围**。 规格里写明这次要做什么的那一部分。
- **非目标**。 规格里明确写出这次不做什么的那一部分，用来防止越做越大。
- **验收条件**。 一条一条可以判断真假的句子，全部为真才算做完。
- **边界情况**。 不在正常路线上的情况，比如输入是空的、网站打不开，规格要写明这时怎么办。
- **隐藏的假设**。 起草的人默认成立却没有写出来的前提，比如默认用户已经登录。
- **原型**。 照着规格做出来的粗糙版本，用来检验规格有没有想清楚。

## 自测

1. 你写下的意图是：“做一个把五个网站的指标汇总到一页的仪表盘。”这句话的主要问题是什么？
   - A. 太短了，没有把验收条件一起写上
   - B. 写的是解决方案，没说谁遇到了什么麻烦
   - C. 没有说明打算用什么技术来实现
   - D. 一次汇总五个网站，范围定得太大

2. 下面四条验收条件，哪一条是合格的？
   - A. 打开页面后三秒内显示全部五个指标
   - B. 页面的加载速度要有明显的提升
   - C. 界面简洁，第一次用的人也能上手
   - D. 各项指标的数据要尽可能准确可靠

3. 你的意图是每天早上少花时间看指标。agent 起草的规格在范围里多了一项：“支持把指标导出成表格并发到邮箱”。你该怎么处理？
   - A. 这个功能挺有用，先留在范围里再说
   - B. 让它给这一项补上可以检查的验收条件
   - C. 先让它做个原型，看看这一项难不难做
   - D. 指出这超出了意图，从范围里拿掉这一项

4. 规格全文没有提到登录，但有一条验收条件写着：“显示当前用户收藏的指标”。按审规格的五点，这里最该指出的是什么？
   - A. 范围被偷偷扩大了，多出导出功能
   - B. 边界情况写得太多，应该删掉几条
   - C. 有没说出来的假设：有用户身份和收藏
   - D. 这条验收条件太长，应该拆成两条写

5. agent 照规格做原型时卡住了：规格没写某个网站打不开时显示什么。它自己决定显示昨天的数字，然后继续做。你该怎么办？
   - A. 回去把这种情况写进规格，再让原型照着改
   - B. 直接告诉它把原型改成你想要的那种显示
   - C. 它的选择挺合理，原型就这样继续往下做
   - D. 原型本来就粗糙，这种细节现在不用理会

6. agent 起草的规格里，非目标一栏是空的。它解释说：“没列进范围的自然就不做，非目标不用单独写。”你怎么判断？
   - A. 接受，范围写清楚了，非目标确实是重复的
   - B. 接受，但要求它把范围再写得更细致一些
   - C. 不接受，非目标要明写，它最能防止越做越大
   - D. 不接受，应该把非目标合并进边界情况里写

<details>
<summary>展开自测答案与解释</summary>

1. **B**。 意图要说清谁、在什么情况下、遇到什么麻烦。一上来就写方案，等于跳过了值不值得做这一问。验收条件属于规格，不属于意图。
2. **A**。 只有这一条能设计出明确通过或不通过的检查：掐表，数指标。“明显提升”听起来像能量，但没有说多少算明显，仍然没法判定。
3. **D**。 这是偷偷扩大范围，审规格第一点就查它。补验收条件最有迷惑性：条件写得再好，也只是把一件没人要求做的事做得更规范。
4. **C**。 “当前用户”和“收藏”都默认了规格里没写过的东西。这类假设不说出来，agent 会按自己的理解去做，你到最后才发现。
5. **A**。 原型卡住的地方往往就是规格没想清楚的地方，要回去改规格。只改原型，规格里这个洞还在，下次照规格做还会掉进去。
6. **C**。 非目标最容易漏，也最能防止越做越大。只靠范围来暗示，做的过程中很容易顺手加上相关的功能，而且没有哪一条可以拿来拦它。

</details>

## 案例练习

### 审一份规格草稿

你的意图是：我每天早上要打开五个网站看指标，很费时间。agent 据此起草了规格。  
范围：一个页面汇总五个网站的指标；支持按周、按月查看历史趋势；指标异常时发邮件提醒。  
非目标：暂无。  
验收条件：1. 页面加载要快。2. 已登录状态下，五个指标全部显示。3. 数据准确可靠。  
边界情况：某个指标为空时显示“暂无数据”。

**请写出你的判断**

这份规格你接受还是打回？写出你发现的每个问题和理由，并按严重程度从高到低排序。

<details>
<summary>展开案例参考分析</summary>

打回。它做的事比意图要求的多，而且做完之后没法判断算不算完成。按严重程度排：

- **范围被扩大了。** 意图只是省掉每天早上逐个打开网站的时间。历史趋势和邮件提醒都没人要求，照这样做下去，工作量会多出好几倍。
- **非目标是空的。** 这一栏空着，就没有任何一条能拦住越做越大。上面多出来的两项，正好应该写在这里。
- **两条验收条件没法检查。** “加载要快”和“数据准确可靠”都设计不出明确通过或不通过的检查。agent 也就没法知道自己做对了没有。
- **藏着一个登录的假设。** 第 2 条默认五个网站都已经登录。没登录或者登录过期时会怎样，规格没有说。
- **出错的情况只写了一种。** 指标为空写了，网站打不开没写。这是每天早上真的会遇到的情况。

排序的依据是错误的代价：范围和非目标决定做的是不是该做的事，排在最前。验收条件决定能不能判断做完，其次。假设和出错情况是规格内部的缺口，补起来最便宜。

</details>

## 复习

先不看题，凭记忆写出好的意图的三个部分、规格要写的四样，以及审规格时看的五点。

1. 意图和规格各自回答什么问题？
   - A. 意图说用什么技术，规格说分几步做
   - B. 意图说做成什么样，规格说为什么做
   - C. 意图说谁来负责，规格说什么时候做完
   - D. 意图说解决什么问题，规格说怎样算完成

2. 规格的四样里，哪一样最容易漏，也最能防止越做越大？
   - A. 范围
   - B. 非目标
   - C. 验收条件
   - D. 边界情况

3. 判断一条验收条件合不合格，该问哪一句？
   - A. 我能不能设计一个检查，让它明确通过或不通过
   - B. 这一条读起来是不是通顺，有没有歧义的词
   - C. 这一条实现起来的工作量会不会太大了
   - D. 这一条是不是把用户所有的期望都写进去了

4. 让 agent 照规格做原型，做到一半卡住了。接下来应该改哪里？
   - A. 直接改原型，让它先跑起来
   - B. 改意图，把问题重新定义一遍
   - C. 回去改规格，把没想清楚的地方写清
   - D. 哪里都不改，换一个 agent 重新做

5. 下面哪一项不在审规格的五点里？
   - A. 它有没有偷偷扩大范围
   - B. 它打算用哪种编程语言
   - C. 每条验收条件能不能检查
   - D. 出错的时候会怎样写了没有

<details>
<summary>展开复习答案与解释</summary>

1. **D**。 意图是一句话，讲问题。规格把“做成什么样算完成”写到可以检查的程度。
2. **B**。 非目标明确写出不做什么。没有它，范围会在做的过程中一点点变大。
3. **A**。 写不出检查方法的条件，agent 也没法知道自己做对了没有。
4. **C**。 卡住的地方往往就是规格没想清楚的地方。规格改好了，原型再照着改。
5. **B**。 五点是：扩大范围、非目标、验收条件能否检查、没说出来的假设、出错时怎样。用什么语言属于怎么做，规格只管做成什么样。

</details>
