## 讲义

机器上所有的文件组织成一棵树，最顶上是根，写作一个斜杠。绝对路径从根写起，在哪里用都指同一个文件；相对路径从当前所在的目录写起，站在不同的目录指的就是不同的文件。这个当前目录叫工作目录，每个进程都有一个，从终端启动的就是终端当时所在的目录，所以文件明明在却报找不到，先查进程是从哪里启动的。每个文件记着它属于哪个用户、哪个组，再对所有者、同组、其他人三类人分别规定读、写、执行，一共九位，ls -l 看，chmod 改。进程以启动它的用户的身份运行；root 几乎什么都能做，sudo 是临时借用 root 的身份。遇到权限拒绝，先查谁在运行、文件归谁，不要直接放开全部权限。环境变量是进程带着的一组名字和值，子进程启动时从父进程复制一份，所以另一个终端看不到这个终端设的变量，改了要从改过的终端重启程序才生效。PATH 列出一串目录，输入命令时系统按顺序去找。

## 术语

- **根**。 文件树最顶上的那一层，写作一个斜杠 /。
- **绝对路径**。 从根开始一层不落写到文件的路径，在哪里用都指同一个文件。
- **相对路径**。 从工作目录写起的路径，站在不同的目录，指的就是不同的文件。
- **工作目录**。 进程当前所在的目录。从终端启动的进程，默认就是终端当时所在的目录。
- **九位权限**。 所有者、同组、其他人三类人，各有读、写、执行三项，三乘三共九位。
- **root 与 sudo**。 root 是几乎什么都能做的特殊用户；sudo 是临时借用 root 的身份运行一条命令。
- **环境变量**。 进程身上带着的一组名字和值，子进程启动时从父进程复制一份。
- **PATH**。 一个环境变量，列出一串目录；输入命令时，系统按顺序去这些目录里找。

## 自测

1. report.py 和 data.csv 都在 ~/project 里，脚本里写的是 open('data.csv')。你在 ~ 目录运行 python3 project/report.py，报 FileNotFoundError。最可能的原因是什么？
   - A. 相对路径从脚本所在的目录算起，一定是文件名拼错了
   - B. 进程的工作目录是 ~，相对路径找的是 ~/data.csv
   - C. data.csv 没有读权限，系统把它报成了找不到文件
   - D. PATH 里没有 ~/project，系统找不到这个数据文件

2. 一个文件的九位权限是 rw-r-----，所有者 pm，所属组 staff。同在 staff 组里的另一个用户，对它能做什么？
   - A. 能读也能写，只是不能执行
   - B. 什么都不能做，只有所有者能碰
   - C. 能读也能执行，只是不能写
   - D. 只能读，不能写，也不能执行

3. 你写好 deploy.sh，运行 ./deploy.sh，终端显示 zsh: permission denied: ./deploy.sh。ls -l 看到它的九位是 rw-r--r--，所有者就是你。最合适的做法是什么？
   - A. 用 chmod +x 给它加上执行权限，再运行
   - B. 改用 sudo 运行，借 root 的身份来执行
   - C. chmod 777，改成所有人都能读写执行
   - D. 把脚本挪到根目录 / 下面，再运行一次

4. 你的 Python 脚本要往 /var/log/app.log 里写日志，报 PermissionError: [Errno 13] Permission denied。最先该查什么？
   - A. 直接 chmod 777，先让脚本跑起来再说
   - B. 改成用 sudo 启动，以后就不会再报
   - C. 先查这个进程以谁的身份运行、文件归谁
   - D. PATH 里有没有 /var/log 这个目录

5. Jupyter 已经开了一上午。你在终端里运行 export API_URL=https://new.example.com，回到笔记本里读 os.environ['API_URL']，还是旧地址。为什么？
   - A. Jupyter 启动时复制了一份，之后的修改它看不到
   - B. export 要过几分钟，才会同步到所有正在运行的进程
   - C. os.environ 只能读系统自带的变量，读不到你设的
   - D. 要用 sudo export 设置，才对所有进程都生效

6. PATH 是 /usr/bin:/opt/homebrew/bin:/bin，两个目录里都有 python3：/usr/bin 里是旧版，/opt/homebrew/bin 里是你新装的。输入 python3，运行的是哪一个？
   - A. 新装的那个，系统总会优先用最近装好的版本
   - B. /usr/bin 里的旧版，按顺序先在那里找到
   - C. 版本号更高的那个，系统会自动比较两者的版本
   - D. 两个都会运行，最后的结果以后运行的为准

<details>
<summary>展开自测答案与解释</summary>

1. **B**。 相对路径从进程的工作目录写起，不是从脚本所在的目录。你在 ~ 启动，工作目录就是 ~，脚本去找 ~/data.csv，那里没有。读权限不够会报 Permission denied，不会说找不到；PATH 管的是去哪里找命令，不管脚本打开的数据文件。
2. **D**。 九位按所有者、同组、其他人分成三组来读，每组三位依次是读、写、执行。中间一组 r-- 只有读。什么都不能做的是最后一组 ---，那是其他人。
3. **A**。 九位里三个 x 都空着，缺的是执行这一位，不是身份不够。sudo 换的是身份，对不上这个问题，还平白把破坏面放到最大；777 能跑，却顺手把写权限给了所有人，放得太宽。
4. **C**。 进程以启动它的用户的身份运行，能不能写取决于这个身份在九位里分到了什么。先弄清谁在运行、文件归谁，再决定怎么改。777 和一律 sudo 都是把范围放到最大，命令一旦写错，破坏面也最大。
5. **A**。 环境变量住在进程里。Jupyter 早上启动时从父进程复制了一份，从此各管各的；你后来改的，只是那个终端进程自己的那份。要在执行过 export 的那个终端里重新启动 Jupyter；只在网页里重启内核不够，内核是从 Jupyter 服务进程复制的，拿到的还是旧值。
6. **B**。 PATH 是一串有先后的目录，系统从左往右找，找到第一个就停。想用新装的，就要把 /opt/homebrew/bin 排到 /usr/bin 前面。

</details>

## 案例练习

### 一份排查记录

同事的记录：  
~/project $ python3 report.py  
（正常）  
~ $ python3 project/report.py  
FileNotFoundError: [Errno 2] No such file or directory: 'data.csv'  
① ls -l ~/project：data.csv 在，rw-r--r--，所有者 pm（就是他）。  
② 还是怀疑权限，运行 sudo chmod -R 777 ~/project，重跑，同样报错。  
③ 结论：Python 坏了，准备重装。

**请写出你的判断**

他的结论对吗？写出真正的原因、他做错的地方和修法，按重要性排序。

<details>
<summary>展开案例参考分析</summary>

结论不对，Python 没坏。按重要性排：

- **真正的原因是工作目录。** 同一个脚本在 ~/project 里能跑，在 ~ 里就报错。open('data.csv') 是相对路径，从进程的工作目录写起，在 ~ 启动，找的就是 ~/data.csv。
- **“Python 坏了”站不住。** 第一次能正常运行，就说明解释器没问题。重装不会改变工作目录，装完照样报错。
- **第②步方向错了，还留下了隐患。** 报错说的是找不到文件，不是 Permission denied。他本来就是所有者，连 sudo 都用不着；777 把整个项目给了所有人读写执行，要改回去。
- **修法很小。** 先 cd ~/project 再运行；或者在脚本里写数据文件的绝对路径，从哪里启动都找得到。

第①步其实做对了：文件在，rw-r--r-- 的所有者 pm 能读，这正好说明问题不在权限上。他看到了证据，却还是去改了权限。

</details>

## 复习

先不看题，凭记忆写出：绝对路径和相对路径的区别、九位权限的三类人和三种操作，以及遇到“找不到文件”和“权限拒绝”时各自先查什么。

1. 绝对路径和相对路径的区别是什么？
   - A. 绝对路径从家目录写起，相对路径从脚本目录写起
   - B. 绝对路径用在终端里，相对路径用在脚本里
   - C. 绝对路径从根写起，相对路径从工作目录写起
   - D. 绝对路径指向文件，相对路径指向目录

2. 九位权限是哪三类人乘哪三种操作？
   - A. 所有者、同组、其他人 × 读、写、执行
   - B. 所有者、同组、其他人 × 读、写、删除
   - C. 所有者、管理员、访客 × 读、写、执行
   - D. 用户、组、root × 读、写、执行

3. sudo 做的是什么？
   - A. 把当前用户永久升级成 root 用户
   - B. 给文件加上所有人都能读写的权限
   - C. 让这条命令跳过权限检查，跑得更快
   - D. 临时借用 root 的身份运行一条命令

4. 一个进程的环境变量是什么时候、从哪里来的？
   - A. 每次读取时，从系统统一的设置里现取
   - B. 启动时，从父进程那里复制一份
   - C. 每隔一段时间，和别的进程自动同步
   - D. 启动时，从磁盘上的程序文件里读出

5. PATH 这个环境变量管的是什么？
   - A. 每个进程当前的工作目录是哪一个
   - B. 脚本里的相对路径从哪个目录算起
   - C. 输入命令后按顺序去哪些目录找
   - D. 哪些命令允许当前这个用户去执行

<details>
<summary>展开复习答案与解释</summary>

1. **C**。 绝对路径从斜杠开始一层不落地写下来，所以不受你在哪里影响。相对路径省掉了前面那段，用工作目录补上，工作目录一变，指的文件就变了。
2. **A**。 三类人是所有者、同组的人、其他所有人，每类三项：读、写、执行。root 不占其中一类，它本来就几乎什么都能做。
3. **D**。 借用只对这一条命令有效。正因为借来的是什么都能做的身份，命令写错时破坏的范围也最大，所以不要什么都加 sudo。
4. **B**。 启动那一刻复制，之后各管各的。所以已经在跑的进程看不到后来的修改，另开的终端也看不到这个终端里设的变量。
5. **C**。 PATH 只和找命令有关。工作目录和相对路径是另一回事，混在一起，就会以为找不到数据文件是 PATH 没配好。

</details>
