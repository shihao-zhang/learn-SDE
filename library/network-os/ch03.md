## 讲义

服务端先在一个端口上监听，开着门等人来；客户端主动发起连接，去敲这扇门。连接建立之后是一条双向的通道，两边都能发数据；没有人监听，连接就无处可连。localhost 指向本机的回环地址，最常见的写法是 127.0.0.1，发往它的数据不出这台机器，所以带 localhost 的地址只在你自己的电脑上有意义。监听时还要选在哪个地址上听：只听回环地址，只有本机的程序连得进来，开发时最安全；听全零地址 0.0.0.0，别的机器也能连进来。本机测试好好的、放到服务器上别人连不上，常见原因是只监听了回环地址。一个连接由本机地址、本机端口、对方地址、对方端口四样东西确定，客户端这一侧的端口由系统临时分配，所以一个服务端口上能同时挂着成千上万个连接。同一个地址加端口同时只能有一个进程监听，再启动一个会报地址已被使用，用 lsof 查是谁占着。每个连接都占资源，能同时打开的数量有上限，用完要关。

## 术语

- **服务端与客户端**。 先在端口上监听、等人来的一方是服务端；主动发起连接的一方是客户端。
- **监听**。 服务端进程占住一个地址加端口，开着门等别人来连。
- **连接**。 客户端主动发起、和服务端之间建立的一条双向通道，两边都能往里发数据。
- **回环地址**。 最常见的写法是 127.0.0.1，localhost 是它的名字。发往它的数据绕一圈回到本机，不出这台机器。
- **全零地址 0.0.0.0**。 监听在它上面，表示这台机器所有的地址都听，别的机器也能连进来。
- **连接的四样东西**。 本机地址、本机端口、对方地址、对方端口。系统靠这四样把每个连接分清楚。
- **客户端端口**。 连接里客户端这一侧的端口，由系统临时分配一个空闲的号码。
- **地址已被使用**。 Address already in use：这个地址加端口已经有进程在监听，不会自动换号的程序再启动就报这个错。

## 自测

1. 你的 Python 脚本用 requests 去访问本机 Jupyter 的接口 localhost:8888。下面哪句说得对？
   - A. Jupyter 是监听的服务端，脚本是发起连接的客户端
   - B. 脚本才是服务端，因为是它先开口、先发出请求的
   - C. 两边都在监听 8888，数据就在这个端口上来回
   - D. 连接建好后，只有脚本能发数据，Jupyter 只能收

2. 你在自己电脑上开着 Jupyter，把 http://localhost:8888/tree 发给坐在旁边、连着同一个 Wi-Fi 的同事。他点开会怎样？
   - A. 能打开，同一个 Wi-Fi 里 localhost 都指你这台
   - B. 能打开，链接会经过公司网络转到你的电脑上
   - C. 他打开的是他自己电脑上的 8888 端口
   - D. 会被转到公司的服务器上，由服务器来打开

3. 你在咖啡馆连着公共 Wi-Fi，开发一个只给自己用的本地服务，不想让同一网络里的其他人连进来。它应该监听在哪个地址？
   - A. 0.0.0.0，所有地址都听，最不容易出问题
   - B. 127.0.0.1，只有本机的程序才连得进来
   - C. 0.0.0.0，再换一个别人猜不到的冷门端口
   - D. 地址无所谓，只要不把端口号告诉别人

4. 同事说：“Jupyter 只占着 8888 这一个端口，所以同一时间只能有一个客户端连着它。”这句话对吗？
   - A. 对，一个端口在同一时刻只能挂着一个连接
   - B. 对，别的客户端要排队，等前一个关掉才行
   - C. 不对，系统给每个客户端另开一个服务端端口
   - D. 不对，每个连接的客户端端口都不一样

5. 你启动一个本地服务（它不会自动换端口），报 OSError: [Errno 48] Address already in use，它要用的是 8080。下一步最合适的是什么？
   - A. 加 sudo 再启动一次，用 root 身份把 8080 抢过来
   - B. 这说明服务的代码写错了，先回去从头检查一遍
   - C. 用 lsof 查谁占着 8080，常是上次没关干净的
   - D. 关掉所有浏览器标签页，是它们占住了 8080

6. 一个脚本每次查询都新开一个连接，用完从不关。刚启动时一切正常，跑了几个小时后，新的连接开始进不来。最可能的原因是什么？
   - A. 服务端的端口被这个脚本独占了，别的连接只能排队
   - B. 连接用久了会自动变慢，要定期重启网络才行
   - C. 本机地址中途变了，旧连接的四样东西对不上了
   - D. 每个连接都占资源，只开不关，把能开的上限用光了

<details>
<summary>展开自测答案与解释</summary>

1. **A**。 谁先在端口上等着，谁就是服务端；谁主动去敲门，谁就是客户端。先开口的是客户端，这正说明它是主动的一方。连接建好后是双向通道，Jupyter 的回答也是顺着它发回来的。
2. **C**。 localhost 永远指“这台机器自己”，谁打开就指谁的电脑。数据绕一个小圈回到本机，根本不出那台电脑，所以碰不到你的 Jupyter；要是他自己也开着一个，看到的就是他自己的。
3. **B**。 只监听回环地址，别的机器从外面进来，那个入口上根本没有人在听。0.0.0.0 是所有地址都听，同一网络的人都能连；端口号冷不冷门挡不住人，号码是可以一个个试出来的。
4. **D**。 服务端的 8888 是固定的，每个连接的客户端端口由系统临时分配，各不相同。四样东西只要有一样不同，就是另一个连接，所以 8888 上可以同时挂着很多个。只能有一个的是监听，不是连接。
5. **C**。 同一个地址加端口同时只能有一个进程监听，报错说的就是已经有一个在听了。先查是谁，常常是上次没关干净、还挂在后台的那个。换成 root 也不能让两个进程同时监听；浏览器标签页是去连的一方，不占监听。
6. **D**。 连接在两边都占一点资源，一个进程能同时打开的连接有上限。只开不关，占着的越积越多，到顶以后新来的就进不来了。刚开始正常、过一阵才出事，正符合这种一点点积累的过程。

</details>

## 案例练习

### 同事说服务好了

同事在公司一台 Linux 服务器（地址 10.0.3.15）上起了一个服务：  
$ uvicorn main:app  
INFO:     Uvicorn running on http://127.0.0.1:8000  
他发来消息：“好了，你打开 http://localhost:8000 就能看。”  
你在自己电脑上打不开。他在服务器上试了一下：  
$ curl localhost:8000  
{"status":"ok"}  
他说：“我这边好好的，是你的网络有问题。”

**请写出你的判断**

他的说法哪里不对？写出你看到的问题，以及要让你连上需要改什么，按排查顺序排。

<details>
<summary>展开案例参考分析</summary>

问题都在他那边，不在你的网络。按排查顺序，从最先挡住你的那一处开始：

- **他给的地址就不对。** localhost 永远指“这台机器自己”。你在自己电脑上打开它，找的是你电脑上的 8000 号端口。至少要给服务器的地址：10.0.3.15:8000。
- **换对地址也连不上：服务只监听了回环地址。** 启动时那行写着 127.0.0.1:8000，只有服务器本机的程序连得进来。要让别的机器连，得让它监听在 0.0.0.0，比如 uvicorn main:app --host 0.0.0.0。
- **他的验证证明不了他的结论。** 他在服务器上 curl localhost，走的是回环，数据没出那台机器。这只能说明服务在本机能用，说明不了别的机器能不能连进来。
- **“你的网络有问题”要排到最后。** 前两处都在他那边。改好监听地址、给对地址之后还连不上，才轮到查网络。

服务本身没问题：进程起来了，8000 号端口有人在听，curl 也拿到了回答，不用去改代码。改成 0.0.0.0 之后，同一网络里的机器都能连进来；只是临时调试的话，用完想一想要不要一直这样开着。

</details>

## 复习

先不看题，凭记忆写出：监听和连接哪个在先、localhost 指哪里、只听回环地址和听 0.0.0.0 的区别、一个连接的四样东西，以及端口被占用时用什么命令查是谁。

1. localhost 指向哪里？
   - A. 你所在的局域网里的那台路由器
   - B. 本机的回环地址，常写作 127.0.0.1
   - C. 0.0.0.0，也就是本机所有的地址
   - D. 公司内网里大家共用的那台开发服务器

2. 一个连接由哪四样东西确定？
   - A. 本机地址、对方地址、进程号、线程号
   - B. 域名、地址、端口号、进程号
   - C. 本机端口、对方端口、本机进程号、对方进程号
   - D. 本机地址、本机端口、对方地址、对方端口

3. 关于“只能有一个”，下面哪句对？
   - A. 一个地址加端口只能有一个进程监听，但能挂很多连接
   - B. 一个端口只能挂一个连接，但能有很多进程同时监听
   - C. 一个地址加端口能有多个进程监听，也能挂很多连接
   - D. 一个端口只能有一个进程监听，也只能挂一个连接

4. 服务监听在 0.0.0.0，意思是什么？
   - A. 不监听任何地址，相当于暂时关掉了
   - B. 只监听回环地址，只有本机能连进来
   - C. 所有的地址都听，别的机器也能连进来
   - D. 这个地址上的所有端口都在同时监听

5. 客户端去连一个没有任何进程在监听的端口，会怎样？
   - A. 连不上，没有人在监听，连接就无处可连
   - B. 系统会临时替它在这个端口上起一个监听
   - C. 先把连接建好，等服务启动后再开始传数据
   - D. 自动改连到旁边一个有人监听的端口上

<details>
<summary>展开复习答案与解释</summary>

1. **B**。 它的意思永远是这台机器自己，发往它的数据不出这台机器。0.0.0.0 是监听时用来表示所有地址都听，和它不是一回事。
2. **D**。 两头各一个地址、一个端口。服务端那头的端口固定，客户端这头的端口由系统临时分配，四样合起来就能分清每一个连接。
3. **A**。 监听是独占的，所以第二个进程会报地址已被使用；连接靠四样东西区分，同一个服务端口上可以同时挂着成千上万个。
4. **C**。 全零地址表示哪个地址都听，说的是地址，不是端口。开发时只听回环地址最安全；需要让别的机器连进来，才改成它。
5. **A**。 顺序不能反：先有人监听，才有地方可连。Jupyter 遇到端口被占会自己换号，那是监听的一方在换，连接的一方不会自己改去别的端口。

</details>
