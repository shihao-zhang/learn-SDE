入门第二课重点读进程、端口及监听。用它们解释本机启动工单台后，浏览器为什么能打开页面。

## 讲义

程序本身只是磁盘上的一个文件，运行起来，操作系统就创建一个进程。每个进程有一个进程号和一块自己的内存，别的进程看不到也碰不到；进程结束，内存由系统收回。一个进程里可以有好几个线程同时干活，它们共享这块内存：交换数据方便，代价是一个线程改坏了共享数据，其他线程跟着出错。线程轮流使用 CPU 的几个核心，切换得很快，看起来像同时在跑。两种满要分清：CPU 满了是算不过来，所有事都在排队；内存满了是放不下，系统先把一部分挪到磁盘，机器明显变卡，再不够就可能有进程被强制结束。进程要让别人找得到，就向系统申请一个端口守在上面，这叫监听；别人用机器地址加端口号找到它。最后是一张总图：机器里有进程、线程、内存、文件系统，端口开在机器的边上，外面是连接、远端服务和域名。

## 术语

- **进程**。 程序运行起来之后的样子。同一个程序运行两次，就是两个进程。
- **进程号**。 系统给每个进程的编号（PID）。活动监视器里每一行都是一个进程。
- **线程**。 一个进程里同时干活的几条线，共享这个进程的内存。
- **内存**。 进程运行时用的那块空间。每个进程一块，互相看不到，进程结束由系统收回。
- **CPU 核心**。 真正做计算的地方。一台电脑通常只有几个到十几个，所有线程轮流用。
- **端口**。 一个从 1 到 65535 的编号，可以理解成进程开在机器边上的一扇门。
- **监听**。 进程向系统申请一个端口，守在上面等别人来。

## 自测

1. 你在两个终端窗口里各运行了一次同一个 Python 脚本，两个都还在跑。活动监视器里会看到什么？
   - A. 一个进程，因为它们来自同一个程序文件
   - B. 一个进程里的两个线程，共享同一块内存
   - C. 两个进程，各有自己的进程号和一块内存
   - D. 两个进程，共用同一个进程号和一块内存

2. 进程 A 里有四个线程，其中一个把一份共享的数据改坏了。最可能跟着出错的是谁？
   - A. 进程 A 里另外几个读这份数据的线程
   - B. 机器上所有正在运行的进程里的全部线程
   - C. 同一个程序启动的另一个进程 B 里的线程
   - D. 只有改坏数据的那一个线程自己会出错

3. 你的电脑只有 8 个 CPU 核心，活动监视器里却有 400 多个进程，看上去都在运行。这是怎么做到的？
   - A. 每个进程启动时分到一个专属核心，用完再还
   - B. 这些进程共用一块内存，所以能放在一起算
   - C. 这 400 多个其实是同一个进程里的线程
   - D. 线程轮流用核心，每次一小段，切换得很快

4. 活动监视器窗口底部的 CPU 总占用接近百分之百（空闲接近 0），内存还剩一大半。这时机器最可能是什么样子？
   - A. 系统开始把内存里的数据挪到磁盘上腾地方
   - B. 所有事都在排队等核心，各种操作都变慢了
   - C. 系统马上强制结束占用最多的那个进程
   - D. 新程序打不开，因为已经放不下更多进程

5. 你同时开着几个读了大数据集的 Jupyter 笔记本。机器越来越卡，过了一会儿，其中一个笔记本提示 The kernel appears to have died。按这一章的说法，最可能发生了什么？
   - A. 内存放不下：先挪到磁盘所以变卡，再不够就结束一个进程
   - B. CPU 算不过来：排队太久的进程，被系统直接结束了
   - C. 内存放不下：系统先结束一个进程，腾出空间后才开始变卡
   - D. 线程改坏了共享数据：几个笔记本共用内存，所以出了错

6. 同事说：“浏览器是靠进程号 4821 找到 Jupyter 的。”这句话错在哪里？
   - A. 没有错，进程号和端口号是同一个编号的两种叫法
   - B. 浏览器靠的是磁盘上 jupyter 这个程序文件的位置
   - C. 进程号会变，浏览器要靠线程号才能找到 Jupyter
   - D. 别的程序找进程靠机器地址加端口号，不靠进程号

<details>
<summary>展开自测答案与解释</summary>

1. **C**。 程序只是磁盘上的文件，每运行一次，系统就创建一个新进程。来自同一个文件不改变这一点：两个进程各有编号、各有内存，互相看不到。
2. **A**。 线程共享所在进程的内存，一个线程写坏的数据，同进程的其他线程读到就会出错。进程之间是隔离的，进程 B 有自己的一块内存，碰不到 A 的数据。
3. **D**。 8 个核心分不出 400 份专属的。线程排队轮流用核心，每次只用一小段时间就换下一个，切换得足够快，看起来就像同时在跑。
4. **B**。 CPU 满是算不过来：线程都在排队等核心，所以样样都慢。挪到磁盘、强制结束、放不下，都是内存满了才有的样子，而这里内存还很空。
5. **A**。 大数据集占的是内存。内存满了，系统先把一部分挪到磁盘，来回搬所以变卡；还不够，才可能强制结束一个进程，顺序不会反过来。CPU 满只会让大家排队变慢。每个笔记本的内核是各自的进程，内存互相隔离，不会被别的笔记本改坏。
6. **D**。 进程号是系统用来管理进程的编号，和外面怎么找到它无关。Jupyter 向系统申请了 8888 号端口、守在上面监听，浏览器说出机器地址加 8888，才找得到它。

</details>

## 案例练习

### 同事的电脑卡了

同事的 Mac 下午突然很卡，他发来活动监视器的读数和自己的判断：  
CPU：8 核，总占用 21%  
内存：16 GB，已用 15.7 GB；已使用的交换（挪到磁盘的部分）6.3 GB  
Chrome：43 个进程，合计占内存 7.9 GB  
他的 Python 脚本：1 个进程，36 个线程，占内存 4.2 GB  
他的判断：① Chrome 有 43 个进程，肯定在抢 CPU；② 脚本的 36 个线程各占一份内存，砍掉一半线程就能省一半内存；③ CPU 才 21%，机器不忙，卡多半是网不好。

**请写出你的判断**

他的三条判断各对不对？写出你认为真正的问题和下一步该做什么，按排查顺序排。

<details>
<summary>展开案例参考分析</summary>

三条都不对。先认出是哪一种满，再逐条排除，最后才动手：

- **先认出是哪种满：内存满了。** 16 GB 已用 15.7 GB，还有 6.3 GB 被挪到了磁盘，正是“放不下”的样子：数据在内存和磁盘之间来回搬，整台机器变卡。卡的原因在这里，不在网络。
- **CPU 没满，“抢 CPU”说不通。** 21% 说明 8 个核心大半空着，线程用不着排队。进程多不等于 CPU 忙。
- **线程共享进程的内存。** 36 个线程用的是这个进程的同一块内存，那 4.2 GB 的数据不会因为少了一半线程就少一半。
- **下一步：按内存排序，关掉用不着的。** Chrome 合计 7.9 GB、脚本 4.2 GB 是大头。动手前先保存手头的东西：再不够，系统可能强制结束某个进程。

CPU 21% 本身没问题，43 个进程这个数字也不说明问题：一台机器上同时跑几百个进程是常态。要看的是 CPU 和内存满没满，满的是哪一样。

</details>

   - C. 程序和进程是同一个东西的两种叫法
   - D. 程序是磁盘上的文件，运行起来才是进程

   - B. 它主动去找别的机器上的某个端口说话
   - C. 它在后台记录机器上所有进程的活动
   - D. 它在等 CPU 空出一个核心给自己用

4. “CPU 满了”和“内存满了”各是什么意思？
   - A. CPU 满了是放不下，内存满了是算不过来
   - B. 两个都是算不过来，只是轻重程度不同
   - C. CPU 满了是算不过来，内存满了是放不下
   - D. 两个都是放不下，只是放的东西不一样

5. 总图里，哪三样画在本机的虚线框外面？
   - A. 端口、连接、域名
   - B. 连接、远端服务、域名
   - C. 线程、内存、文件系统
   - D. 连接、远端服务、文件系统

<details>
<summary>展开复习答案与解释</summary>

1. **B**。 每个进程有自己的一块内存，别的进程碰不到；同一进程里的线程共用这块内存。所以线程协作方便，也容易互相连累。
2. **D**。 程序躺在磁盘上，不占进程号。每运行一次，系统就创建一个进程，所以同一个程序可以同时对应好几个进程。
3. **A**。 监听是被动地等：先占住一个端口，别人用机器地址加端口号来找它。主动去找别人是另一回事，第 3 章会把这两端分开讲。
4. **C**。 CPU 满，线程排队，样样都慢；内存满，系统先挪到磁盘而变卡，再不够可能结束进程。先分清是哪一种满，才知道该往哪里查。
5. **B**。 框里是进程、线程、内存、文件系统；端口开在框的边上，像一扇门；从门出去的连接、连接另一头的远端服务、帮你找到它的域名都在框外。

</details>
